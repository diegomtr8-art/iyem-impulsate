BUG 1 — 404 EN PERFIL DE PROVEEDOR
───────────────────────────────────────────────────────

PROBLEMA DETECTADO:
En routes/web.php existe una ruta duplicada con el mismo nombre:

  // Ruta pública (fuera del grupo auth):
  Route::get('/restauranteros/{restaurantero}', [RestauranteroPublicoController::class, 'show'])
       ->name('restauranteros.show');  ← nombre 'restauranteros.show'

  // Ruta de admin (dentro del grupo admin con middleware):
  Route::get('/restauranteros/{restaurantero}', [RestauranteroAdminController::class, 'show'])
       ->name('restauranteros.show');  ← MISMO nombre, sobreescribe la anterior

Esto causa que cuando un proveedor logueado intenta ver su perfil público,
Laravel resuelve el helper route('restauranteros.show', $id) hacia la ruta
del admin, que exige middleware 'admin', y devuelve 403 o 404.

ADEMÁS: en RestauranteroPublicoController::show() hay:
  abort_if(!$restaurantero->activo, 404);
Si el restaurantero no tiene activo = true, da 404 aunque sea el dueño.

CORRECCIONES:

1. En routes/web.php, cambiar el nombre de la ruta de admin:
   ANTES: ->name('restauranteros.show')
   DESPUÉS: ->name('admin.restauranteros.show')
   (busca esta línea dentro del grupo admin prefix('admin'))

2. En todos los archivos que usen route('restauranteros.show') dentro del
   contexto admin, actualizar a route('admin.restauranteros.show').
   Buscar con: grep -r "restauranteros.show" resources/js/Pages/Admin/

3. Para el problema de activo=false causando 404 al propio proveedor:
   En RestauranteroPublicoController::show(), cambiar la lógica:
   - Si el usuario autenticado es el dueño del restaurantero O es admin:
     permitir acceso aunque !$restaurantero->activo
   - Si es visitante público: mantener abort_if(!$restaurantero->activo, 404)

   Código de la corrección:
   ```php
   $esdueno = auth()->check() && auth()->id() === $restaurantero->user_id;
   $esAdmin = auth()->check() && auth()->user()->hasRole('admin');
   abort_if(!$restaurantero->activo && !$esDueno && !$esAdmin, 404);
   ```

4. Verificar que el link "Ver mi perfil público" en el panel proveedor
   (Restaurantero/Panel.vue) use la ruta correcta:
   route('restauranteros.show', restaurantero.id)
   Y que ese ID corresponda al restaurantero del usuario, no a otro.

5. Probar el fix con: php artisan route:list | grep restauranteros
   Verificar que no haya nombres de ruta duplicados.

```php
        'leida'    => false,
    ]);

    // Notificación in-app al proveedor (dueño del restaurantero)
    if ($cita->restaurantero?->user_id) {
        Notificacion::create([
            'user_id'  => $cita->restaurantero->user_id,
            'tipo'     => 'recordatorio_1h',
            'titulo'   => '¡Cita en 1 hora!',
            'mensaje'  => 'Tienes una cita con ' . ($cita->cliente->name ?? 'un comprador')
                        . ' a las ' . $cita->inicio->format('H:i') . 'h.',
            'leida'    => false,
        ]);
    }

    $cita->update(['recordatorio_1h_enviado' => true]);
}
```
