===========================================================================
PUNTO 2 — Sección "Explora los proveedores de la plataforma" en la página pública de Proveedores
===========================================================================
HALLAZGO: la página pública `resources/js/Pages/Restauranteros/Index.vue` (la que muestra
"Proveedores del Evento: {nombre del evento}" / "Explora y agenda citas con los mejores proveedores
del sector.") hoy SOLO lista proveedores aprobados que estén registrados como proveedor en el
evento activo (`evento_usuario.tipo = 'proveedor'` y `estado = 'aprobado'`). Si no hay evento activo,
no se muestra ningún proveedor (pantalla "No hay un evento activo en este momento").

Lo que se pide: agregar, al final de esa misma página, una sección nueva llamada "Explora los
proveedores de la plataforma" que muestre TODOS los proveedores activos con perfil completo,
independientemente del evento — es decir, un directorio general de la plataforma, separado de la
lista específica del evento de arriba. Esta sección debe verse tanto si hay evento activo como si
no lo hay (en ese segundo caso, es la única lista que tendrá contenido).

DECISIONES DE DISEÑO (confirmar con Diego si prefiere algo distinto):
- Filtro de la sección nueva: `Restaurantero.activo = true` AND `Restaurantero.aprobado = true` AND
  `User.perfil_completo = true`. Se exige también `aprobado = true` aunque no se pidió explícitamente,
  porque un proveedor no aprobado no debería ser visible públicamente en ningún listado — si Diego
  quiere que la sección ignore la aprobación, avisar antes de quitar esa condición.
- Esta sección NO excluye a los proveedores que ya aparecen en la lista del evento activo de arriba
  — puede haber proveedores repetidos entre ambas secciones, ya que tienen propósitos distintos
  (uno es "quién participa en este evento", el otro es "todo el directorio de la plataforma"). Si se
  prefiere que la sección de abajo excluya a los que ya están arriba, es un cambio menor (agregar
  `whereNotIn('id', $idsYaMostrados)`), pero no se asume aquí.
- Paginación independiente para no interferir con la paginación de la lista del evento (parámetro de
  query distinto: `plataforma_page`).

2A. Backend
---------------
Archivo: app/Http/Controllers/RestauranteroPublicoController.php

Modificar `index()` (línea 12-77) para construir siempre la lista de plataforma, tanto si hay
evento activo como si no, y pasarla en ambos `Inertia::render`:

```php
public function index(Request $request)
{
    $evento = Evento::activo();

    $proveedoresPlataforma = Restaurantero::query()
        ->where('activo', true)
        ->where('aprobado', true)
        ->whereHas('user', fn ($q) => $q->where('perfil_completo', true))
        ->withCount('citas')
        ->orderByDesc('created_at')
        ->paginate(8, ['*'], 'plataforma_page')
        ->withQueryString();

    if (!$evento) {
        return Inertia::render('Restauranteros/Index', [
            'restauranteros'         => [],
            'sin_evento'             => true,
            'filters'                => $request->only(['search', 'categoria']),
            'categorias'             => [],
            'proveedoresPlataforma'  => $proveedoresPlataforma,
        ]);
    }

    $query = Restaurantero::query()
        ->where('activo', true)
        ->where('aprobado', true)
        ->whereHas('user', function ($q) use ($evento) {
            $q->whereExists(function ($sub) use ($evento) {
                $sub->from('evento_usuario')
                    ->whereColumn('evento_usuario.user_id', 'users.id')
                    ->where('evento_usuario.evento_id', $evento->id)
                    ->where('evento_usuario.tipo', 'proveedor')
                    ->where('evento_usuario.estado', 'aprobado');
            });
        })
        ->withCount('citas')
        ->orderByDesc('created_at');

    if ($request->filled('search')) {
        $search = $request->search;
        $query->where(function ($q) use ($search) {
            $q->where('nombre_restaurante', 'like', "%{$search}%")
              ->orWhere('direccion', 'like', "%{$search}%")
              ->orWhere('descripcion', 'like', "%{$search}%");
        });
    }

    if ($request->filled('categoria')) {
        $query->where('categoria', $request->categoria);
    }

    $categorias = Restaurantero::where('activo', true)
        ->where('aprobado', true)
        ->whereHas('user', function ($q) use ($evento) {
            $q->whereExists(function ($sub) use ($evento) {
                $sub->from('evento_usuario')
                    ->whereColumn('evento_usuario.user_id', 'users.id')
                    ->where('evento_usuario.evento_id', $evento->id)
                    ->where('evento_usuario.tipo', 'proveedor')
                    ->where('evento_usuario.estado', 'aprobado');
            });
        })
        ->whereNotNull('categoria')
        ->distinct()
        ->orderBy('categoria')
        ->pluck('categoria');

    $restauranteros = $query->paginate(12)->withQueryString();

    return Inertia::render('Restauranteros/Index', [
        'restauranteros'        => $restauranteros,
        'sin_evento'            => false,
        'filters'               => $request->only(['search', 'categoria']),
        'categorias'            => $categorias,
        'proveedoresPlataforma' => $proveedoresPlataforma,
    ]);
}
```
(El cuerpo del bloque "con evento activo" es idéntico al actual, solo se le agrega la nueva
variable `proveedoresPlataforma` al `Inertia::render` final, y se calcula `proveedoresPlataforma`
una sola vez arriba para cubrir ambos casos.)
