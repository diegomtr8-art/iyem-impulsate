PUNTO 3 — Cambiar el correo de envío a impulsate@iyemyucatan.com (cuenta de Gmail/Google Workspace)
===========================================================================
HALLAZGO IMPORTANTE: no hay ningún correo "from" puesto a mano en el código. Los 11 Mailables
(app/Mail/*.php: CitaAgendada, CitaConfirmada, CitaCancelada, CitaAceptada, CitaRechazada,
CitaReagendada, ProveedorAprobado, ProveedorRechazado, RecordatorioCita, EncuestaSatisfaccionMail,
PlantillaCorreoMail) y todos los controladores usan `Mail::to(...)->send(...)` sin sobrescribir el
remitente, así que TODOS obedecen una sola configuración global: `config('mail.from.address')`,
que se lee de la variable de entorno `MAIL_FROM_ADDRESS`.

Esto significa que este punto NO requiere cambios de código — es 100% configuración del servidor
(.env), y el archivo .env NO está en el repositorio de Git (por seguridad), así que Claude Code no
puede aplicarlo solo: hay que hacerlo a mano por SSH en el servidor.

DIFERENCIA IMPORTANTE: impulsate@iyemyucatan.com es una cuenta de Gmail/Google Workspace, NO un
buzón de Hostinger. Esto cambia el host/puerto SMTP y, sobre todo, cambia qué "contraseña" se debe
usar:

- Google ya NO permite usar la contraseña normal de la cuenta para SMTP en la inmensa mayoría de
  los casos (desactivó el acceso de "apps menos seguras"). Hay que generar una "Contraseña de
  aplicación" (App Password) de 16 caracteres, específica para SMTP, distinta de la contraseña de
  inicio de sesión.
- Para poder generar una contraseña de aplicación, la cuenta de Google necesita tener activada la
  Verificación en 2 pasos (2FA).

ESTADO: Diego ya generó la Contraseña de aplicación de 16 caracteres para impulsate@iyemyucatan.com
(con la Verificación en 2 pasos activa). Esa contraseña de aplicación NO debe escribirse en ningún
archivo del repositorio ni pasarse a Claude Code como texto — solo se pega directamente en el .env
del servidor, a mano, por quien tenga acceso SSH. Por seguridad, dado que esa contraseña de
aplicación quedó escrita en una conversación de chat, conviene revocarla en
https://myaccount.google.com/apppasswords y generar una nueva una vez confirmado que todo funciona,
para que la que circuló en el chat quede inválida.

PASOS (por SSH, los hace Diego o quien tenga acceso al servidor — no se sube por git)
------------------------------------------------------------------------------------------
1. Entrar al servidor por SSH y editar el archivo .env (en la raíz del proyecto en producción):
   nano .env
2. Verificar/actualizar estas líneas (servidor SMTP de Google, no el de Hostinger):
   MAIL_MAILER=smtp
   MAIL_HOST=smtp.gmail.com
   MAIL_PORT=587
   MAIL_USERNAME=impulsate@iyemyucatan.com
   MAIL_PASSWORD=<pegar aquí la contraseña de aplicación de 16 caracteres, sin espacios>
   MAIL_ENCRYPTION=tls
   MAIL_FROM_ADDRESS="impulsate@iyemyucatan.com"
   MAIL_FROM_NAME="Encuentro de Negocios Impulsate"
3. Guardar y salir, luego limpiar caché de configuración:
   php artisan config:clear
   php artisan config:cache
4. Enviar un correo de prueba. Lo más simple es por Tinker:
   php artisan tinker
   Mail::raw('Prueba de configuración de correo Impulsate', function ($m) {
       $m->to('iyem.informatica@iyemyucatan.com')->subject('Prueba SMTP Impulsate');
   });
   Si se envía sin error y llega a esa bandeja, la configuración quedó correcta. Si Google rechaza
   la conexión, revisar que la contraseña de aplicación se copió completa (sin espacios) y que la
   verificación en 2 pasos esté realmente activa en la cuenta.

Nota: en el repositorio, .env.example y DEPLOY.md ya muestran impulsate@iyemyucatan.com pero con
los datos SMTP de Hostinger (smtp.hostinger.com:465) — como el correo real es Gmail/Google
Workspace, conviene actualizar también esos dos archivos de referencia para que no confundan a
futuro (cambiar host/puerto/encriptación a los de Gmail indicados arriba).
