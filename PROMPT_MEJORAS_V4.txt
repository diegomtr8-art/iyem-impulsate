CAMBIO 3: Encuesta de satisfacción post-evento
==========================================
Objetivo: cuando un evento finaliza (o el admin lo marca como finalizado/archivado), se envía un correo a cada participante (proveedores y compradores que hayan estado registrados/aprobados en ese evento) invitándolo a contestar una encuesta de satisfacción. Las respuestas se guardan y el admin puede exportarlas a Excel.

Implementación:
1. Migraciones:
   - `encuestas_satisfaccion`: id, evento_id (FK eventos), user_id (FK users), tipo (enum: comprador/proveedor), token (string único, para acceso sin login), completada_at (nullable timestamp), timestamps.
   - `encuesta_respuestas`: id, encuesta_satisfaccion_id (FK), pregunta (string), respuesta (text), timestamps. (Diseño flexible tipo "key-value" para que cuando el usuario envíe el cuestionario definitivo más adelante, no haya que migrar de nuevo el esquema — solo cambiar las preguntas que se renderizan en el formulario).
2. Modelos: `EncuestaSatisfaccion` (relaciones con Evento, User, hasMany EncuestaRespuesta) y `EncuestaRespuesta`.
3. Preguntas por defecto (definir como constante/array en el controlador o un archivo de config `config/encuestas.php`), aplicar las MISMAS preguntas para proveedor y comprador por ahora:
   - "¿Cómo calificarías tu experiencia general en el evento?" (escala 1-5)
   - "¿Las citas agendadas cumplieron tus expectativas?" (escala 1-5)
   - "¿La organización y logística del evento fue adecuada?" (escala 1-5)
   - "¿Qué fue lo que más te gustó del evento?" (texto libre)
   - "¿Qué podríamos mejorar para futuros eventos?" (texto libre)
   - "¿Recomendarías participar en futuros eventos de Impúlsate?" (Sí/No)
   Dejar comentado en el código un TODO indicando que esta lista será reemplazada cuando el usuario proporcione el cuestionario oficial.
4. Controlador público `EncuestaController` (sin middleware auth, acceso por token):

5. Trigger de envío de correos:

     b. Por cada uno, crear un registro `EncuestaSatisfaccion` con token único (`Str::random(40)`) si no existe ya uno para ese user+evento.
     c. Enviar correo `app/Mail/EncuestaSatisfaccion.php` (Mailable nuevo) con el link `route('encuestas.responder', $token)`, usando plantilla Markdown con la identidad visual guinda.
6. Panel de administración:

   - Vista `Admin/Encuestas/Index.vue`: tabla filtrable por evento, con columnas Usuario, Tipo (proveedor/comprador), Estado (respondida/pendiente), Fecha de respuesta.
   - Botón "Exportar a Excel" -> usar maatwebsite/excel (igual patrón que ExportController existente) para generar un Excel con todas las respuestas (una fila por encuesta, columnas = preguntas, agrupable o con hoja por evento si aplica el patrón `WithMultipleSheets` ya usado en el proyecto).
