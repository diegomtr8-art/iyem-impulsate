CAMBIO 4: Módulo "Publicidad" (pop-up al iniciar sesión)
==========================================
Objetivo: el super-admin sube una imagen publicitaria con un hipervínculo opcional, define una ventana de fechas de vigencia, y esa imagen aparece como pop-up modal a compradores y proveedores justo después de iniciar sesión (o al cargar el panel), mientras esté dentro de la ventana de fechas y "activa". El usuario puede cerrarla con la X o la tecla Esc. Las publicidades pasadas/desactivadas quedan archivadas para poder reactivarlas después.

1. Migración + modelo `Publicidad`:
   - Tabla `publicidades`: id, titulo (string, solo para identificación interna en el panel admin), imagen (string, ruta en storage), enlace (string nullable - puede ser URL externa `https://...` o ruta interna `/algo`), abre_en_nueva_pestana (boolean, solo aplica si el enlace es externo), fecha_inicio (datetime), fecha_fin (datetime), activa (boolean, default true), timestamps.
2. Modelo `Publicidad` con scope `vigente()`: `activa = true AND fecha_inicio <= now() AND fecha_fin >= now()`.
3. Controlador `Admin/SuperAdmin/PublicidadController.php`:
   - `index`: lista todas las publicidades (vigentes, programadas, expiradas/archivadas), con badge de estado calculado.
   - `store`: validar imagen (`image|mimes:jpg,jpeg,png,webp,gif|max:5120`), `enlace` (nullable, url o ruta relativa - validar formato básico), `fecha_inicio`/`fecha_fin` (`fecha_fin > fecha_inicio`), `activa`. Guardar imagen en `storage/app/public/publicidad/`.
   - `update`: permitir editar todos los campos, incluyendo re-subir imagen (borrar la anterior si se reemplaza) y reactivar una publicidad pasada (cambiar fechas y/o `activa = true` para "reutilizar" un anuncio archivado, tal como pidió el usuario).
   - `toggleActiva`: activar/desactivar manualmente sin borrar.
   - `destroy`: eliminar definitivamente (con confirmación en frontend) - borra también el archivo de imagen.
   - Solo puede existir lógicamente UNA publicidad "vigente" mostrándose a la vez para no saturar al usuario; si hay varias vigentes simultáneamente (fechas solapadas), mostrar la más reciente (`orderByDesc('fecha_inicio')->first()`) - documentar este comportamiento con un comentario en el código.
4. Vistas en `resources/js/Pages/Admin/SuperAdmin/Publicidad/`:
   - `Index.vue`: tabla/galería de tarjetas con miniatura de la imagen, título, enlace, rango de fechas, estado (Vigente/Programada/Expirada/Inactiva), acciones (Editar, Activar/Desactivar, Eliminar).
   - `Form.vue` (crear/editar, modal o página): subir imagen con preview, campo enlace, checkbox "abrir en nueva pestaña" (solo si enlace es externo), selectores de fecha/hora inicio y fin, checkbox activa.
5. Lógica de visualización del pop-up (frontend):
   - En `HandleInertiaRequests.php`, agregar al share global una prop `publicidadActiva` que devuelva los datos de la publicidad vigente (id, imagen URL, enlace, abre_en_nueva_pestana) SOLO si el usuario autenticado tiene rol `cliente` o `restaurantero` (no mostrar al admin/super-admin), o `null` si no hay ninguna vigente.
   - Crear componente `resources/js/Components/PublicidadPopup.vue`:
     - Modal centrado con overlay oscuro semitransparente, la imagen a tamaño responsivo (max-width controlado, `object-contain`), botón "X" en la esquina superior derecha.
     - Si `enlace` está presente, la imagen completa es clickeable (`<a>` o `@click` con `router.visit`/`window.open` según `abre_en_nueva_pestana` y si es URL externa o ruta interna - usar Inertia `Link`/`router.visit` para rutas internas, `window.open` para externas).
