3. Flujo de auto-aprobación
Comparativo entre el flujo actual (con aprobaciones manuales) y el nuevo flujo donde todo se aprueba automáticamente. El único paso manual que queda es la aprobación al evento.
❌ Flujo ACTUAL (con aprobaciones manuales)
1. Usuario se registra en la plataforma
2. Usuario llena datos básicos (teléfono, CURP...)
3. 🔑 Admin aprueba en /admin/restauranteros
4. Proveedor llena su perfil en Panel.vue
5. 🔑 Admin revisa si el perfil está completo
6. Proveedor solicita entrar al evento
7. 🔑 Admin aprueba la solicitud al evento
8. Proveedor ya aparece en el directorio
⚠️ Requiere 3 intervenciones manuales del admin
⚠️ Proveedores con perfil incompleto pueden quedar sin detectar
⚠️ El comprador también necesita aprobación manual
✅ Flujo NUEVO (auto-aprobación)
1. Usuario se registra en la plataforma
2. 🧙 Wizard obliga a completar TODO el perfil
3. ✅ Al guardar → aprobado = true automático
4. ✅ Se solicita automáticamente al evento activo
5. ✅ Solicitud de evento auto-aprobada
6. Proveedor ya aparece en el directorio
✅ 0 intervenciones manuales para el perfil
✅ Perfil siempre 100% completo antes de ser público
✅ Admin solo usa el módulo Agenda para organizar citas
¿Qué pasa con el módulo "admin/restauranteros"?
El módulo sigue existiendo pero solo se usa para consulta y edición, no para aprobar perfiles. La lista mostrará todos los proveedores ya aprobados automáticamente. El admin puede desactivar o bloquear un proveedor si detecta un problema, pero la aprobación inicial es automática.

Filtro de compradores: Si el comprador no marca "¿Eres restaurantero?", puede completar su perfil y acceder a la plataforma pero NO puede solicitar registro al evento. La solicitud al evento solo se auto-aprueba si marcó ser restaurantero.
