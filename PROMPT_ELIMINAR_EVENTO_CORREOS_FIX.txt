CAMBIO 1 — CORREGIR BOTONES CTA EN CORREOS

--------
Las plantillas de correo tienen URLs incorrectas que causan server error
cuando el usuario hace click desde su email.

Causa raíz: la ruta real del panel de proveedores es /proveedor/panel
(prefix 'proveedor' en web.php), pero las plantillas usaban
/restaurantero/panel que NO existe como ruta — dispara 500.

pública, nunca dispara 500, y desde ahí el usuario puede iniciar sesión
y navegar a su panel. Es el único CTA seguro para correos donde el
usuario puede o no estar autenticado.

PASO 2B — NUEVO MÉTODO eliminar() EN EventoSolicitudesController
----------------------------------------------------------------
Agregar este método al final de la clase, antes del cierre }:

    public function eliminar(Evento $evento, User $user, Request $request)
    {
        $request->validate([
            'motivo_eliminacion' => 'required|string|max:500',
        ]);

        $registro = DB::table('evento_usuario')
            ->where('evento_id', $evento->id)
            ->where('user_id', $user->id)
            ->where('estado', 'aprobado')
            ->first();

        if (!$registro) {
            return back()->withErrors(['error' => 'Registro no encontrado o no está aprobado.']);
        }

        // Cancelar citas activas del usuario en el sistema
        if ($registro->tipo === 'proveedor') {
            $restaurantero = $user->restaurantero;
            if ($restaurantero) {
                \App\Models\Cita::where('restaurantero_id', $restaurantero->id)
                    ->whereNotIn('estado', ['cancelada', 'rechazada', 'completada'])
                    ->update(['estado' => 'cancelada']);
            }
        } else {
            \App\Models\Cita::where('cliente_id', $user->id)
                ->whereNotIn('estado', ['cancelada', 'rechazada', 'completada'])
                ->update(['estado' => 'cancelada']);
        }

        // Eliminar el registro del evento para que pueda re-postularse
        DB::table('evento_usuario')
            ->where('evento_id', $evento->id)
            ->where('user_id', $user->id)
            ->delete();

        // Notificar al usuario
        $tipoTexto = $registro->tipo === 'proveedor' ? 'como proveedor ' : '';
        Notificacion::crear(
            $user->id,
            'solicitud_rechazada',
            'Eliminado del evento',
            'Has sido eliminado ' . $tipoTexto . 'del evento "' . $evento->nombre . '". Motivo: ' . $request->motivo_eliminacion . '. Puedes volver a postularte.'
        );

        return back()->with('success', 'Usuario eliminado del evento.');
    }

   "Ir a la plataforma" → mismo resultado.

   botón "Eliminar del evento" en cada tarjeta.

   la alerta amarilla con el conteo de citas.

5. Al confirmar eliminación → usuario desaparece de Aprobados → sus
   citas quedan en estado 'cancelada' → puede volver a postularse.
