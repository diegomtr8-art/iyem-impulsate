PROMPT PARA CLAUDE CODE — FIX AGENDA: 405 Method Not Allowed
El botón "Aceptar" del correo da error 405 porque la ruta es POST
pero los links de email siempre hacen GET.
Archivo: FIX_AGENDA_405_GET.txt
================================================================================

PROBLEMA:
  URL del error: impulsate.iyemyucatan.com/agenda/aceptar/{token}
  Error: 405 Method Not Allowed
  
  Causa: Las rutas agenda.aceptar y agenda.rechazar están definidas como
  Route::post(...), pero los botones del correo son links <a href="...">,
  que el navegador abre con GET. Laravel rechaza la petición con 405.

  Los links de email SIEMPRE son GET — nunca POST. Hay que cambiar las
  rutas a GET y el controller debe manejar GET.

OBJETIVO:
  1. Cambiar rutas a GET para que los links del correo funcionen
  2. Verificar que al aceptar se crean las citas en el sistema
  3. Verificar que las citas aparecen en /mi-panel del comprador
  4. Verificar que al rechazar el admin recibe notificación visible
  5. Deploy

LEE TODOS LOS ARCHIVOS ANTES DE MODIFICAR.

CAMBIO 1 — routes/web.php: cambiar POST a GET en las rutas públicas de agenda
════════════════════════════════════════════════════════════════════════════════

Busca el bloque de rutas de agenda pública. Debe verse así actualmente:

    Route::prefix('agenda')->name('agenda.')->group(function () {
        Route::get('/propuesta/{token}',  [..., 'ver']);
        Route::post('/aceptar/{token}',   [..., 'aceptar']);   // ← PROBLEMA
        Route::post('/rechazar/{token}',  [..., 'rechazar']);  // ← PROBLEMA
    });

Cámbialo a:

    Route::prefix('agenda')->name('agenda.')->group(function () {
        Route::get('/propuesta/{token}',  [AgendaPublicaController::class, 'ver'])->name('ver');
        Route::get('/aceptar/{token}',    [AgendaPublicaController::class, 'aceptar'])->name('aceptar');
        Route::get('/rechazar/{token}',   [AgendaPublicaController::class, 'rechazar'])->name('rechazar');
    });

IMPORTANTE: Estas rutas deben estar FUERA de cualquier grupo con middleware
'auth' o 'verified'. El comprador abre el link sin estar logueado en el server.
Verifica que no estén dentro de Route::middleware(['auth'])->group(...).

    {

                    $propuesta->user_id,
                    'agenda_aceptada',
                    '¡Agenda confirmada!',
                    'Has confirmado tu agenda de citas para el evento "' .

            'tipo'         => 'aceptada',
            'propuesta'    => $propuesta->load([

            ]),
            'yaRespondida' => false,
        ]);

CAMBIO 3 — AgendaPublicaController.php: método rechazar() con GET
════════════════════════════════════════════════════════════════════════════════

Reemplaza el método rechazar() completo por:

    public function rechazar(string $token)
    {
        $propuesta = AgendaPropuesta::where('token', $token)
            ->with(['comprador:id,name,nombre_empresa', 'evento:id,nombre'])
            ->firstOrFail();

        // Protección contra doble-click
        if (!$propuesta->esPendiente()) {
            return Inertia::render('Agenda/Gracias', [
                'tipo'         => $propuesta->estado,
                'propuesta'    => $propuesta,
                'yaRespondida' => true,
            ]);
        }

        $propuesta->update([
            'estado'        => 'rechazada',
            'respondida_at' => now(),
        ]);

        $nombreComprador = $propuesta->comprador->nombre_empresa
                           ?? $propuesta->comprador->name;

        // Notificar a TODOS los admins
        $admins = \App\Models\User::role(['admin', 'super-admin'])->get();
        foreach ($admins as $admin) {
            if (class_exists(\App\Models\Notificacion::class)) {
                \App\Models\Notificacion::crear(
                    $admin->id,
                    'agenda_rechazada',
                    '⚠️ Agenda rechazada — re-propuesta necesaria',
                    'El comprador "' . $nombreComprador . '" rechazó su propuesta de agenda ' .
                    'para el evento "' . $propuesta->evento->nombre . '". ' .
                    'Ve a Admin → Agenda para generar una nueva propuesta.'
                );
            }
        }

        // Notificar al comprador que su rechazo fue registrado
        if (class_exists(\App\Models\Notificacion::class)) {
            \App\Models\Notificacion::crear(
                $propuesta->user_id,
                'agenda_rechazada',
                'Propuesta rechazada registrada',
                'Recibimos tu respuesta. El equipo de IMPULSATE te contactará pronto ' .
                'para generarte una nueva propuesta de agenda.'
            );
        }

        return Inertia::render('Agenda/Gracias', [
            'tipo'         => 'rechazada',
            'propuesta'    => $propuesta,
            'yaRespondida' => false,
        ]);
    }
