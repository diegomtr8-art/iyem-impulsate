CONTEXTO:
  Los eventos de tipo 'encuentro_negocios' tienen flujo de registro con rol
  proveedor/comprador, ventanas temporales, citas, etc. — NO TOCAR nada de eso.

  Los eventos de tipo 'bazar_exposicion' necesitan un flujo completamente
  distinto y simplificado: cualquier usuario autenticado ve un solo botón
  "Solicitar participación", lo confirma en el modal, y espera su correo
  de aprobado o rechazado. Sin rol, sin citas, sin ventanas temporales.

CAMBIO 2 — Nuevo método en EventoRegistroController.php

    public function registrarBazar(Request $request, Evento $evento)
    {
        // Solo para eventos de tipo bazar
        if ($evento->tipo_evento !== 'bazar_exposicion') {
            throw ValidationException::withMessages([
                'error' => 'Este evento no es de tipo Bazar/Exposición.',
            ]);
        }

        // El evento debe estar activo
        if (!$evento->activa) {
            throw ValidationException::withMessages([
                'error' => 'Este evento no está activo.',
            ]);
        }

        // Si el evento ya finalizó
        if ($evento->fecha_hora_fin && now()->gt($evento->fecha_hora_fin)) {
            throw ValidationException::withMessages([
                'error' => 'Este evento ya ha finalizado.',
            ]);
        }

        $user = $request->user();

        // Verificar si ya está registrado
        $registro = DB::table('evento_usuario')
            ->where('evento_id', $evento->id)
            ->where('user_id', $user->id)
            ->where('tipo', 'expositor')
            ->first();

        if ($registro) {
            if (in_array($registro->estado, ['pendiente', 'aprobado'])) {
                return back()->with('success', 'Ya tienes una solicitud registrada para este evento.');
            }
            // Si fue rechazado: volver a poner en pendiente
            DB::table('evento_usuario')
                ->where('evento_id', $evento->id)
                ->where('user_id', $user->id)
                ->where('tipo', 'expositor')
                ->update([
                    'estado'          => 'pendiente',
                    'motivo_rechazo'  => null,
                    'respondido_at'   => null,
                    'seleccionado'    => false,
                    'updated_at'      => now(),
                ]);
        } else {
            DB::table('evento_usuario')->insert([
                'evento_id'   => $evento->id,
                'user_id'     => $user->id,
                'tipo'        => 'expositor',   // nuevo tipo para bazar
                'estado'      => 'pendiente',
                'seleccionado'=> false,
                'created_at'  => now(),
                'updated_at'  => now(),
            ]);
        }

        // Notificar al admin
        $admin = User::role('admin')->first();
        if ($admin) {
            Notificacion::crear(
                $admin->id,
                'solicitud_registro',
                'Nueva solicitud de bazar',
                $user->name . ' solicita participar en "' . $evento->nombre . '".'
            );
        }

        return back()->with('success',
            'Tu solicitud fue enviada. Te notificaremos por correo cuando sea revisada.');
    }

════════════════════════════════════════════════════════════════════════════════
NOTAS IMPORTANTES
════════════════════════════════════════════════════════════════════════════════

1. El campo tipo = 'expositor' es nuevo en evento_usuario. La tabla ya tiene
   el campo tipo como string, así que no necesita migración. Solo se inserta
   con ese valor nuevo.

2. El evento de tipo 'bazar_exposicion' NO tiene restricción de rol: cualquier
   usuario autenticado puede registrarse, sin importar si es restaurantero,
   cliente, o no tiene perfil completo. La evaluación la hace el admin.

3. El flujo del Solicitudes admin (Admin/Eventos/Solicitudes.vue) probablemente
   filtra por tipo 'proveedor'/'comprador'. Verificar que también muestre
   registros con tipo 'expositor' para los bazares. Si filtra, agregar el
   tipo 'expositor' a la consulta.

4. El módulo de Encuestas y Correo Masivo también filtran por tipo/rol. Para
   eventos bazar, los 'expositor' son los participantes. Si en el futuro se
   quiere enviar correos masivos a expositores, agregar tipo 'expositor' a
   los filtros relevantes.

VERIFICACIÓN
════════════════════════════════════════════════════════════════════════════════

Con un evento de tipo 'bazar_exposicion' activo:

1. Usuario con cualquier rol (o sin rol) entra a su Dashboard
2. Ve la card del evento activo SIN el timeline de fases
3. Ve solo la fecha del evento (si está configurada)
4. Ve el botón "Solicitar participación" (no "como proveedor" ni "como comprador")
5. Hace click → modal dice "Para solicitar tu participación en..."
6. Confirma → se inserta en evento_usuario con tipo='expositor', estado='pendiente'
7. La card muestra "Solicitud enviada — pendiente de revisión"
8. El admin ve la solicitud en /admin/eventos/{id}/solicitudes

Con un evento de tipo 'encuentro_negocios' activo:
   → Todo sigue exactamente igual que antes, sin ningún cambio
