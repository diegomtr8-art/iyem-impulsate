  // ¿Está abierto el registro de proveedores?
  public function registroProveedoresAbierto(): bool {
      $inicio = $this->fecha_hora_inicio_proveedores;
      $fin    = $this->fecha_hora_fin_proveedores;
      if ($inicio && now()->lt($inicio)) return false;
      if ($fin && now()->gt($fin)) return false;
      return true;
  }

  // ¿Está abierto el registro de compradores?
  public function registroCompradoresAbierto(): bool {
      $inicio = $this->fecha_hora_inicio_compradores;
      $fin    = $this->fecha_hora_fin_compradores ?? $this->fecha_hora_fin;
      if ($inicio && now()->lt($inicio)) return false;
      if ($fin && now()->gt($fin)) return false;
      return true;
  }

  // Segundos hasta que abre el registro de proveedores (null si ya abrió)
  public function segundosHastaProveedores(): ?int {
      if (!$this->fecha_hora_inicio_proveedores) return null;
      $diff = now()->diffInSeconds($this->fecha_hora_inicio_proveedores, false);
      return $diff > 0 ? $diff : null;
  }

  // Segundos hasta que abre el registro de compradores
  public function segundosHastaCompradores(): ?int {
      if (!$this->fecha_hora_inicio_compradores) return null;
      $diff = now()->diffInSeconds($this->fecha_hora_inicio_compradores, false);
      return $diff > 0 ? $diff : null;
  }

CAMBIO 4 — CUENTAS REGRESIVAS EN LA PESTAÑA EVENTOS
=========================================================

Crear componente: resources/js/Components/CuentaRegresiva.vue

Props:
  segundos: Number          (segundos hasta el evento objetivo, desde el servidor)
  label: String             (ej: "Apertura de registro de proveedores en")
  labelCero: String         (ej: "¡El registro de proveedores ya está abierto!")

Lógica:
  - Al montar, iniciar countdown con setInterval cada 1 segundo
  - Calcular días, horas, minutos, segundos restantes
  - Cuando llega a 0: emitir evento 'completed', mostrar labelCero
  - Al llegar a 0: emitir 'completed' y llamar router.reload() después de 3 segundos
    para que el panel se actualice con el nuevo estado (apertura de registro)
  - Limpiar el intervalo en onUnmounted

DISEÑO del componente (Tailwind, dark mode):
  - Fondo: bg-guinda-50 dark:bg-guinda-950/20, borde guinda
  - Label en la parte superior, tamaño pequeño
  - Los 4 bloques: DD | HH | MM | SS con el número grande (text-3xl font-bold)
    y la etiqueta debajo (días, horas, min, seg) en texto pequeño
  - Separador ":" entre bloques
  - Cuando quedan menos de 1 hora: los bloques de horas/minutos/seg se vuelven
    text-red-600 dark:text-red-400 para indicar urgencia
  - En móvil: los 4 bloques en una fila con números más pequeños (text-2xl)

USO en TabEventos.vue:
  Mostrar CuentaRegresiva SOLO cuando la ventana correspondiente no ha abierto:

  // Para proveedores: cuando aún no abre el registro de proveedores
  <CuentaRegresiva
    v-if="evento.segundos_hasta_proveedores"
    :segundos="evento.segundos_hasta_proveedores"
    label="El registro de proveedores abre en:"
    label-cero="¡El registro de proveedores ya está abierto!" />

  // Para compradores: cuando el registro de compradores no ha abierto
  <CuentaRegresiva
    v-if="evento.segundos_hasta_compradores && !registroProveedorAbierto"

    label="El agendado de citas abre en:"
    label-cero="¡Ya puedes registrarte como comprador!" />

NOTA: Los segundos vienen del servidor en el prop del componente.
El cliente hace countdown local desde ese valor. Al llegar a 0 hace
router.reload() para obtener el estado actualizado del servidor.

CAMBIO 7 — BUG: SWITCH DE ROL NO ACTUALIZA EL FRONTEND
=========================================================

CAUSA DEL BUG:
  SwitchRoleController hace redirect()->route('dashboard').
  Inertia intercepta el redirect y navega internamente, pero los props
  compartidos (auth.user.active_role, registradoEnEvento) no se refrescan
  completamente en todos los navegadores porque Inertia reutiliza la
  instancia de Vue sin hacer una visita completa.

CORRECCIÓN EN BACKEND (SwitchRoleController.php):

  // ANTES:
  return redirect()->route('dashboard');

  // DESPUÉS: Forzar visita completa de Inertia
  return Inertia::location(route('dashboard'));

  // Inertia::location() hace un redirect HTTP real (302) que obliga al
  // browser a hacer una visita completa, recargando todos los shared props.
  // Importar: use Inertia\Inertia;

CORRECCIÓN EN FRONTEND (AppLayout.vue):

  // ANTES:
  router.post(route('switch.role'), {}, {
      onFinish: () => { switchingRole.value = false; },
  });

  // DESPUÉS: añadir onSuccess para limpiar estado,
  // Inertia::location() ya maneja el reload, pero por si acaso:
  router.post(route('switch.role'), {}, {
      onSuccess: () => {
          switchingRole.value = false;
          // No necesitamos router.reload() porque Inertia::location hace
          // una visita completa del servidor
      },
      onError: () => { switchingRole.value = false; },
      onFinish: () => { switchingRole.value = false; },
  });
